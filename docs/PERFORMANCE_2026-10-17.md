# 2026-10-17 游玩帧率优化

用户确认范围：电脑 Chrome / Edge 游玩帧率低；流畅优先，允许适度降低画质。保留已选四种人物、办公室、五区玩法和现有存档格式。修改前已确认方案。

## 当前结果与测量边界

本机 Intel HD Graphics 630，内置 Chromium / WebGL 2，CSS 视口 1920×1080。同一可见前台场景、同一移动与镜头负载，预热 4 秒后采样 15 秒；自动模式预热 14 秒。帧时间使用真实墙钟间隔，未用模拟 dt 或 GPU 读回代替 FPS。

最终连续 A/B 复核：

| 模式 | 平均 FPS | P50 帧时间 | P95 帧时间 | P99 帧时间 | 内部渲染尺寸 |
| --- | ---: | ---: | ---: | ---: | --- |
| 优化前中预设 | 27.2 | 35.4 ms | 51.5 ms | 60.0 ms | 1920×1080 |
| 优化后中预设，关闭自动调节 | 31.8 | 30.4 ms | 44.3 ms | 52.2 ms | 1920×1080 |
| 优化后中预设，自动流畅 | 43.9 | 22.5 ms | 34.7 ms | 41.0 ms | 1115×627 |

固定预设平均 FPS 提高 17.2%；自动模式提高 61.6%。固定预设保留 FXAA，去掉了叠加的 MSAA。自动模式以清晰度和效果换取帧率，不能当成原分辨率的性能提升。

最终 A/B 原始数据：`qa/performance-v2-recheck-before-1080p.json`、`qa/performance-v2-recheck-fixed-1080p.json`、`qa/performance-v2-recheck-auto-1080p.json`。固定预设的平均场景 CPU 耗时由 16.6 ms 降为 10.0 ms，动画目标数由 1095 减为 318。

最终一分钟持续测试：平均 35.1 FPS，P95 48.3 ms，P99 72.5 ms；分段平均约 31–41 FPS。原始数据 `qa/performance-v2-auto-60s-final.json`。持续稳定 60 FPS 尚未达到，不能仅以较好的短时结果宣布达标。

较早的同场景测试为 41.2 → 49.0 FPS，自动模式 59.6 FPS；第一版自动策略一分钟平均 48.7 FPS。对应未带 recheck 的 v2 报告和 initial 报告全部保留作为诊断记录。这些结果与最终运行存在明显差异，原因未确证，不把差异归因于本轮代码，也不将不同时段的最好值拼为一个结论。早期无 v2 的报告曾逐帧切换动作，仅用于诊断；720p 数据不与 1080p 数据混算。

这些是本机单场景测量，未完成独立 Chrome / Edge、全设备、长时间热降频或真人通关性能验收。当前证明有性能提升，尚不能证明所有设备流畅或恒定 60 FPS。五区功能回归使用明确的定位与时间推进控件，不作为正常通关时长。

## 改动与代码职责

- `ModelLibrary.ts`：停止 glTF 自动启动的模板动画。隐藏模板仍保留在 Scene 中，保证家具实例正常接收后续创建或切换的灯光。
- `CharacterRig.ts`：统一可见性与动画生命周期，离区/隐藏时停止动画，回来时恢复选中动作；缓存 Idle/Walk/Run 查找。角色动画目标数由 1095 降为 318。NPC 与玩家的控制、AI 和外观继续解耦。
- `OfficeWorld.ts`：建立当前区域遮挡列表；避免逐帧遍历全部约 1253 个网格。静态变换和包围盒固定；门与电梯面板明确排除，仍能移动。未改变导航阻挡数据。遮挡淡化保留 AI 视线阻挡。
- `NavigationSystem.ts` / `GuideRoutePlanner.ts`：用扩张矩形与线段求交替代每 0.15 米采样，精确检测薄墙，门锁变化立即生效。巡逻路径、发现规则、移动速度与互动时间不变。
- `Game.ts`：关闭冗余的 MSAA 与 preserveDrawingBuffer；FXAA 由性能管理器统一拥有。真实帧间隔与碰撞保护用的 capped dt 分开。
- `AdaptiveQuality.ts`：纯策略模块，默认开启。先预热 3 秒，每 2 秒检查持续平均帧时间；高于 18.5 ms 时逐级降低。四个降级档位分别限制渲染比例、像素预算、后处理、局部灯光、阴影、粒子与 FXAA。最末档限制为约 70 万内部像素，关闭动态局部灯光和 FXAA；保留基础照明、人物、家具和功能标记。忽略暂停、后台和大于 250 ms 的单次停顿。
- `PerformanceManager.ts`：只应用有效画质、分辨率和当前区域阴影投射列表。动态结果不写入用户保存的设置；窗口尺寸变化保留当前自动档位。
- `GameUI.ts`：增加「自动调节画质，优先流畅」开关；显示 FPS 时也显示实际内部渲染尺寸。可关闭自动调节恢复手动画质；任务列表仅在完成状态变化时更新 DOM；低帧率时关闭全屏噪点叠层。

自动调节只在当前评估期间向下，避免 60 Hz 上限附近反复变清晰/模糊。显式应用设置或刷新会重新评估；当前不自动回升。效果限制遵循用户选项，不会开启用户关闭的阴影或灯光。原始模型、运行时 GLB 与许可证未改动。

## 重测方法

1. `npm test`、`npm run build`、`npm run qa`。
2. `npm run dev`，打开 `http://127.0.0.1:5186/?qa=1`，此页使用独立 QA 存档与设置。
3. 将前台视口固定为 1920×1080。点击「中画质帧率对比」或「自动流畅帧率对比」，保持页面前台，等待结果自动暂停；保存 qa-report。
4. 「自动流畅持续 60 秒」在 14 秒预热后连续记录 60 秒。不要同时运行构建或其他重负载任务。
5. 生产页不包含上述控件。正常用户可在设置中开启「显示帧率」，观察实际渲染尺寸和 FPS。

生产画面证据：`qa/screenshots/performance-production-20261017.jpg`；正式构建验证：`qa/performance-production-smoke.json`。
